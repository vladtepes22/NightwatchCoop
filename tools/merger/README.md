# Mod merger

Merges Nightwatch Co-op mod folders into one new mod folder that the launcher's Mods page lists.

```
python -I -B -X utf8 merger.py merge --game <game dir> --out <new mod folder> --log <log file> --mod <dir> [--mod <dir> ...]
```

- `--mod` order is the merge order: when two mods change the same thing, the later one wins. A conflict never stops
  the merge.
- `--out` must not exist. The merge writes into `<out>.tmp`, renames it at the end and deletes it on failure.
- Each log line goes to the log file and to stdout (UTF-8). Prefixes: `CONFLICT`, `NOT MERGED`, `MERGED` (one per
  merged file), `COPIED`, `INFO`. The last line is `DONE <n> files, <n> conflicts`. Exit 0 on success; otherwise
  `ERROR <message>` on stderr and a non-zero exit.
- Base: the game's update folder first, then the game. The game is only read.
- Item names and param field names in the log are read from the game (and the mods) at merge time. The repo holds no
  game text or data.

## What merges

Every change is compared 3-way against the game's file. A file that only one mod changed is taken byte for byte.

| Files | Unit | Notes |
|---|---|---|
| PARAM (in `gameparam.parambnd` etc.) | a row field | Field layout from the game's paramdefs; each bitfield bit range is its own unit. A number is one unit, so two mods that change different bits of one number conflict and do not mix. Without a paramdef that fits the row size, 4-byte words. Rows are keyed (id, nth occurrence); duplicates pair by equal content first. A new row goes after the last row with the next-lower id; the table is never re-sorted. A row size that differs from the game's makes the table later-wins with one `NOT MERGED` line. Row names merge too (later wins); rows two mods name differently (often a translation) get one `INFO` line per table, not a CONFLICT each, as the game does not use row names. A new row two mods add differently is one CONFLICT naming the fields that differ (with each mod's values when three or fewer). A row one mod deletes and another changes: the later of them decides, with a CONFLICT line. |
| FMG | a text id | Long texts in the log are cut near the first difference. |
| BND4 (format 0x74) | an inner file | Matched by file name when names are unique (a mod's engGB msgbnd may say engUS inside), else by path; the game's path is kept. Inner PARAM, FMG, TPF, TAE, hks and BND4 merge by content. Others: later mod wins with a CONFLICT line. |
| TPF | a texture name | |
| TAE (TAE3, little-endian 64-bit) | an animation id | A changed animation is copied whole from the winning mod. The result is read back and checked against its sources. |
| hks (text) | a top-level statement (function) | Change detection uses `hks_base.json`: hashes of the community decompile, generated by `gen_hks_base.py` (the decompile is not shipped). For a file not in it, the first mod's text is the base (INFO line). |
| `nightwatch\*.json` | a row key | Same rules as the engine: hit_effects (attacker_speffect, base_fx / sp_attribute), weapon_clip_groups (weapon), sounds (event; WAVs copied, a name clash goes under `merged/<mod>/`), animated_attachments (the whole row, part in any case). Rows are checked as the engine checks them: a bad row is left out alone (the engine would drop that mod's whole table), a key listed twice in one table keeps the later row, and the merged table keeps the engine's limits (rows, 1 MiB) by leaving out the earliest mods' rows first; each with an `INFO` line. `nightwatch.json` is written: requires = the highest input, features = the union. |

DCX files are unpacked, merged and re-packed as DFLT, zlib level 9 (files on a thread pool), with the game file's
DCX header (the last mod's for a file the game has not). Two DCX files with the same content count as the same file.

## What does not merge

The later mod's whole file wins, with a `NOT MERGED` line: MSB (maps), EMEVD (events), behaviour graphs and other
Havok files, models, effects, compiled AI scripts, menu files, BND4 binders in other formats (shader binders), and a
merge unit that cannot be read. A file only one mod ships is copied (`COPIED`). Files beside a mod's game files
(readme, images, `nocturne.json`) are not copied (INFO line).
